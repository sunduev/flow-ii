## Контекст и границы продукта

Работа ведётся в репозитории `chr-flow`. Нужно создать статический сайт истории одного ежегодного турнира: команды и места по годам, состав выбранной команды на конкретном проведении, полные цепочки участников этого состава за все известные годы. Другие турниры, аккаунты, редактор данных и отдельные страницы игроков не входят в первую версию.

Стек: Vite + TypeScript + SVG + `d3-scale`/`d3-shape`, обычный CSS, без React, сервера и базы данных. Данные загружаются из статического JSON. В `docs/references/tournament-history.html` сохранён необязательный визуальный ориентир, а не утверждённый дизайн. Можно улучшать оформление и удобство, сохраняя сценарии продукта. Целевое размещение — GitHub Pages.

## Обязательные правила данных

- Схема версии 1 по контракту: проведение (`id`, `year`, `name`), команда (`id`, `name`), игрок (`id`, `name` формата «Имя Ф.»), участие (`id`, `editionId`, `teamId`, `displayName`, `place`, `playerIds`). ID — строки, год и ID источника извлекаются из имени XLSX по контракту, название передаётся со списком файлов; одно проведение на год.
- Данные по умолчанию корректны и полны; считаем, что игрок входит в одну команду на одном проведении. Проверки дублей, ссылок, конфликтов и метаданных не реализуются.
- Состав и название берутся из конкретного участия. Переименование с сохранением ID и возвращение игрока сохраняют историю; совпадение имён не объединяет разных игроков.
- Цепочка описывает известные участия в этом турнире. Годы без данных не заполняются; связь через пропущенные годы — пунктирная. Фильтр диапазона не создаёт новых участий или связей.
- Равные и дробные места сохраняются: отдельные строки, место без округления, стабильный лексикографический порядок по строковому ID команды. Не ограничивать состав шестью игроками; статусы полноты не нужны.

## Цель и входные данные

Создать запускаемый каркас проекта и примеры данных, на которых следующий агент сможет реализовать цепочки и интерфейс без таблицы пользователя. Предыдущие майлстоуны не требуются. Репозиторий может содержать только план, задания и макет; проверить его состояние перед изменениями.
