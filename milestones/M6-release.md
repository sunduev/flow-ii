## Контекст и границы продукта

Работа ведётся в репозитории `chr-flow`. Нужно создать статический сайт истории одного ежегодного турнира: команды и места по годам, состав выбранной команды на конкретном проведении, полные цепочки участников этого состава за все известные годы. Другие турниры, аккаунты, редактор данных и отдельные страницы игроков не входят в первую версию.

Стек: Vite + TypeScript + SVG + `d3-scale`/`d3-shape`, обычный CSS, без React, сервера и базы данных. Данные загружаются из статического JSON. В `docs/references/tournament-history.html` сохранён необязательный визуальный ориентир, а не утверждённый дизайн. Можно улучшать оформление и удобство, сохраняя сценарии продукта. Целевое размещение — GitHub Pages.

## Обязательные правила данных

- Схема версии 1 по контракту: проведение (`id`, `year`, `name`, необязательное `tournamentId`), команда (`id`, `name`), игрок (`id`, `name` формата «Имя Ф.»), участие (`id`, `editionId`, `teamId`, `displayName`, `place`, `playerIds`). ID — строки, год и ID источника извлекаются из имени XLSX по контракту, название передаётся со списком файлов; одно проведение на год.
- Данные по умолчанию корректны и полны; считаем, что игрок входит в одну команду на одном проведении. Проверки дублей, ссылок, конфликтов и метаданных не реализуются.
- Состав и название берутся из конкретного участия. Переименование с сохранением ID и возвращение игрока сохраняют историю; совпадение имён не объединяет разных игроков.
- Цепочка описывает известные участия в этом турнире. Годы без данных не заполняются. Пунктир означает пропуск игроком промежуточного проведения из полного набора, а не календарный разрыв. Фильтр диапазона не создаёт новых участий или связей.
- Равные и дробные места сохраняются: отдельные строки, место без округления, стабильный лексикографический порядок по строковому ID команды. Не ограничивать состав шестью игроками; статусы полноты не нужны.

## Цель и входные данные на начало этапа

Опубликовать проверенную первую версию на GitHub Pages и описать добавление нового года без изменения кода интерфейса. Требуются завершённый M5, готовый JSON, команды отдельного скрипта и сборки, целевой репозиторий GitHub и доступ для настройки публикации. Проверить параметры репозитория и принятый способ публикации; не придумывать публичный адрес.

Уже готовы: `scripts/convert-xlsx.ts`, `data/sources.json`, 20 реальных XLSX и `public/data/tournament-history.json` (20 проведений за 2001–2008, 2010–2019, 2025–2026 годы; 400 команд, 2557 игроков, 1240 участий). Команды: `npm ci`, `npm run convert:xlsx`, `npm test`, `npm run typecheck`, `npm run build`, `npm run preview`. Загрузчик JSON использует `import.meta.env.BASE_URL`; фактический base сборки ещё нужно настроить. Локальный Git существует, remote не настроен; конфигурация публикации и отчёт M6 отсутствуют на момент актуализации.

M5 завершён 2 октября 2026 года на реальном наборе. Его отчёт сохраняет историческую приёмку; после неё удалены текстовые списки и верхний выбор команды, введены карточки состава, масштабирование, перетаскивание и закреплённые годы. Последняя приёмка годов и клавиатуры — [отчёт от 4 октября](../docs/reports/2026-10-04-sticky-years.md). M6 повторяет актуальный сценарий, а не прежний интерфейс M5.

От пользователя до публикации нужны:

- URL существующего GitHub-репозитория либо владелец и имя нового с поручением создать его; для нового репозитория — публичность. Существующие настройки и ветки изучить самостоятельно после получения доступа.
- Доступ на запись в репозиторий и настройку Pages/Actions через авторизованное локальное окружение; секреты в документацию не записывать. Объём поручения должен включать необходимые коммиты, push, настройку публикации и саму публикацию.
- Вариант адреса: стандартный GitHub Pages либо конкретный собственный домен. Для собственного домена нужны его имя и возможность настроить DNS; стандартный URL определить по фактическому репозиторию и настройкам Pages.

Новый XLSX для старта не требуется. Процедуру добавления года проверить на отдельном временном наборе. Для проверки обновления кеша без реального обновления подготовить отдельную тестовую публикацию в пределах того же поручения; если её нельзя разместить в выбранном репозитории, зафиксировать недостающий вход.

Исходные XLSX сохраняются только локально и исключены из Git и его истории. В новом клоне для повторного преобразования нужно отдельно получить таблицы; сборка и публикация используют готовый JSON из Git. Не добавлять обязательный запуск `convert:xlsx` в процесс публикации, которому исходники недоступны. README должен явно разделять получение локальных исходников и сборку готового сайта.

Если доступа или целевого репозитория нет, можно подготовить локальную конфигурацию и инструкции, но публикацию считать ожидающей входных данных. Не объявлять сайт опубликованным без проверки публичного адреса.

## Актуальный сценарий приёмки

На компьютере и телефонном размере: выбрать команду мышью/касанием → открыть кнопку людей → прочитать исторический состав и место → выбрать имя игрока → увидеть его цепочку до и после выбранного года → сузить диапазон, сохранив выбранное участие и фильтр → вернуть скрытый год для повторного открытия состава → снять фильтр крестиком или повторным нажатием имени → выбрать другую команду. Начальное состояние — все годы, лучшая команда последнего доступного проведения и цепочки всего её состава.

Отдельной кнопки «Весь состав», нижней панели и текстовых списков истории нет. Название проведения сохраняется в JSON; карточка показывает название команды, год, место и игроков. Полные истории вычисляются по всему набору; диапазон ограничивает только диаграмму. Кнопка цепочки у связанного участия показывает игроков выбранных цепочек и подпись источника состава.

Проверить «Компактно», масштаб 10–200% и сброс процента к 100%, приближение двойным кликом при масштабе ниже 100%, перетаскивание мышью и нативную прокрутку на телефоне. Годы закреплены при вертикальной прокрутке и совпадают с колонками при горизонтальной прокрутке и масштабе; самый новый слева. Клавиатурой проверить управление, ссылки годов, кнопки состава, имена игроков, снятие фильтра и Escape с возвратом фокуса. Узлы команд исключены из Tab: выбор произвольной команды клавиатурой не является критерием M6. Фоновые связи не отображаются.
