## Контекст и границы продукта

Статический сайт истории одной серии ежегодного турнира: команды и места по годам, состав выбранной команды и полные цепочки игроков. Стек: Vite + TypeScript + SVG + `d3-scale`/`d3-shape`, CSS. Сайт читает готовый JSON; подготовка XLSX выполняется отдельным локальным скриптом. Формы загрузки, функции импорта на сайте, сервер и редактор не нужны.

## Модель и допущения

- Схема версии 1: проведение (`id`, `year`, `name`), команда (`id`, `name`), игрок (`id`, `name`), участие (`id`, `editionId`, `teamId`, `displayName`, `place`, `playerIds`). ID — строки; URL и дата проведения не хранятся.
- Источники и метаданные считаются корректными и полными. Не реализовывать валидаторы данных, поиск дублей и конфликтов, отчёты диагностики или процедуры подтверждения.
- Город и флаг игнорируются; в JSON сохраняется «Имя Ф.» без отчества. Все игроки сохраняются; состав не ограничивается шестью, дробные места не округляются.
- Справочники объединяются по ID. Имена игроков и справочные названия команд берутся из последнего проведения; исторические названия и составы остаются в участиях.
- Проверки кода на корректных примерах сохраняются; обычные технические ошибки чтения/записи файлов достаточно показать стандартным сообщением скрипта.

## Цель и входные данные

Создать скрипт, преобразующий ежегодные XLSX в формат приложения и сохраняющий результат в нужное место. Требуются завершённые M1–M3, XLSX в `data/source/` с именами `tournament-with-players-<tournamentId>-<year>.xlsx` и название каждого проведения в `data/sources.json`. ID источника и год извлекаются из имени файла; внутренние ID JSON остаются на основе года.

Готовые тестовые данные в `public/data/tournament-history.json` описаны в `data/fixtures/README.md`; при подключении реальных проведений заменить условную историю результатом скрипта.

Формат изучен на `tournament-with-players-12826.xlsx`: лист `Worksheet`, 574 строки игроков, 90 команд, составы 6–9, дробные места. Соответствие колонок описано в контракте. Старый образец нужно переименовать с фактическим годом; также нужно его название. Для реальной истории по годам нужны остальные XLSX в новом формате имени и названия проведений. Пока входов нет, можно реализовать скрипт на корректных примерах, но не объявлять подключение всей реальной истории завершённым.
