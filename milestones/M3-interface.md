> Актуализация от 4 октября 2026 года после завершения M3–M5: пользователь согласовал замену нижней панели карточкой состава с переключением фильтра игрока, удаление текстовых списков истории и увеличение диаграммы до оставшейся высоты окна. Текущий сценарий: команда → карточка состава → игрок → снятие фильтра → другая команда. Диапазон сохраняет выбор; состав открывается только кнопкой людей в диаграмме. Фильтр находится рядом с периодом/«Компактно»; верхняя подпись команды и отдельная строка проведения удалены, место показано в карточке. Узлы команд исключены из Tab, годы закреплены при прокрутке. Требования и отметки ниже сохраняют исходное задание и приёмку M3; текущий интерфейс описан в [общем плане](../docs/plan.md), проверка закреплённых годов — в [отчёте от 4 октября](../docs/reports/2026-10-04-sticky-years.md), последние проверки маски имён — в [отчёте от 6 октября](../docs/reports/2026-10-06-surname-initial-mask.md).

## Контекст и границы продукта

Работа ведётся в репозитории `chr-flow`. Нужно создать статический сайт истории одного ежегодного турнира: команды и места по годам, состав выбранной команды на конкретном проведении, полные цепочки участников этого состава за все известные годы. Другие турниры, аккаунты, редактор данных и отдельные страницы игроков не входят в первую версию.

Стек: Vite + TypeScript + SVG + `d3-scale`/`d3-shape`, обычный CSS, без React, сервера и базы данных. Данные загружаются из статического JSON. В `docs/references/tournament-history.html` сохранён необязательный визуальный ориентир, а не утверждённый дизайн. Можно улучшать оформление и удобство, сохраняя сценарии продукта. Целевое размещение — GitHub Pages.

## Обязательные правила данных

- Схема версии 1 по контракту: проведение (`id`, `year`, `name`), команда (`id`, `name`), игрок (`id`, `name` формата «Имя Ф.»), участие (`id`, `editionId`, `teamId`, `displayName`, `place`, `playerIds`). ID — строки, год и ID источника извлекаются из имени XLSX по контракту, название передаётся со списком файлов; одно проведение на год.
- Данные по умолчанию корректны и полны; считаем, что игрок входит в одну команду на одном проведении. Проверки дублей, ссылок, конфликтов и метаданных не реализуются.
- Состав и название берутся из конкретного участия. Переименование с сохранением ID и возвращение игрока сохраняют историю; совпадение имён не объединяет разных игроков.
- Цепочка описывает известные участия в этом турнире. Годы без данных не заполняются; связь через пропущенные годы — пунктирная. Фильтр диапазона не создаёт новых участий или связей.
- Равные и дробные места сохраняются: отдельные строки, место без округления, стабильный лексикографический порядок по строковому ID команды. Не ограничивать состав шестью игроками; статусы полноты не нужны.

## Цель и входные данные

Собрать интерактивный интерфейс на демонстрационных данных. Требуются завершённые M1 и M2: каркас, схема, JSON и функции вычисления цепочек. Макет можно использовать как источник идей; улучшать композицию, оформление и удобство по требованиям продукта. Точное воспроизведение не требуется.

## Обязательное поведение интерфейса

Годы — колонки слева направо от новых к старым, самый новый год слева; команды — строки по месту с явными подписями. Выбор команды выделяет полные цепочки всего её исторического состава и открывает панель с названием, годом, местом и игроками. Выбор игрока показывает только его цепочку; «Весь состав» возвращает выделение всех участников. В панели для каждого выделенного игрока есть полная текстовая последовательность «год → команда», включая годы вне диапазона диаграммы.

В панели также показать `edition.name`; при скрытом выбранном году название остаётся доступным. Полная текстовая цепочка идёт от старых лет к новым. Место `6.5` отображается без округления (допустимо `6,5` по русской локали). Имя игрока показывать как «Имя Ф.». При совпадении сокращённых подписей разных игроков добавлять к доступной подписи ID, чтобы их можно было различить.

Изначально показаны все годы и выбран победитель последнего доступного турнира. При равном первом месте выбрать по стабильному порядку ID; при отсутствии первого места — команду с наименьшим местом. Пустые данные не вызывают ошибку.
