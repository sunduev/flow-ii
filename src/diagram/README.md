# Диаграмма — M3

`pan.ts` подключается один раз к контейнеру, сохраняется после замены SVG и меняет только `scrollLeft`/`scrollTop`. Левая кнопка мыши начинает перетаскивание после 5 px, затем захватывает указатель и подавляет последующий клик. Короткие нажатия и клавиатурные клики сохраняются; этот модуль игнорирует touch и перо. Прокрутка закрывает карточку на десктопе; на телефоне карточка сохраняется и обновляет положение. Два пальца отдельно обрабатывает `pinch.ts`.

`renderDiagram` получает проекцию M2, индекс, выбор и callback участия. SVG размещает годы по убыванию, команды по порядку результатов M2; d3-scale задаёт колонки, d3-shape строит плавные связи. Фоновые связи не создаются в SVG; линии выделенных игроков окрашены контрастной палитрой по порядку строковых ID полного выбранного состава и смещены по позиции в нём. Цвета совпадают с маркерами карточки и сохраняются при выборе игрока, смене диапазона и компактности. В режиме одного состава выбор другого участия может изменить цвет игрока; в режиме «Все составы» выбор другого года той же команды сохраняет палитру общего набора. Смещение ограничено высотой узла, число игроков не ограничено. isGap задаёт пунктир при пропуске игроком проведения из полного набора. Годы с tournamentId — SVG-ссылки на rating.chgk.info в новой вкладке; старые наборы без поля отображаются без ссылок. Узлы имеют tabindex=-1 и пропускаются при Tab; Enter/пробел работают при программном фокусе. Годы вынесены в отдельный sticky-слой общей области прокрутки, масштабируются вместе с SVG; текстовые факты не восстанавливаются из SVG. Контейнер прокрутки и диапазон принадлежат странице.

Проекция `src/history/diagram-view.ts` оставляет активные участия и исходные связи. Тот же renderer уплотняет их по колонкам без неактивных DOM-узлов. `geometry.ts` вычисляет исходные размеры SVG. `zoom.ts` масштабирует существующий SVG через transform и задаёт фактический размер `.diagram-stage`; overflow clip исключает исходный большой SVG из области прокрутки при уменьшении. `zoomScroll` сохраняет центр в координатах исходного SVG и ограничивает прокрутку на краях. Масштаб хранится в `main.ts` отдельно от выбора и передаётся renderer при необходимой замене SVG. Нажатия масштаба renderer не вызывают.

`createTeamInfo` управляет одной карточкой. Карточка состава содержит название команды, год, отдельную строку места и весь список кнопок игроков; отдельной строки названия проведения нет. Она доступна у активного участия, а в режиме «Все составы» — у всех показанных участий выбранной команды. Внешние карточки связей содержат место, информационный список и подпись источника состава. `getTeamInfoPlayerIds` отделяет полный состав конкретного участия от фильтра выделения.

Состав открывается только из диаграммы. После переключения игрока SVG заменяется; карточка находит новую кнопку по ID участия, сохраняет размещение и фокусирует имя. Escape возвращает фокус на кнопку людей. `main.ts` показывает снимаемый фильтр рядом с периодом и «Компактно». Повторное нажатие имени использует `togglePlayer`, удаление верхнего фильтра — `selectPlayer(selection, null)` с фокусом на «Компактно». Верхней подписи команды и дополнительных кнопок состава нет.

`enableDiagramDoubleClickZoom` подключается один раз к постоянному контейнеру. При масштабе меньше 100% второй click (detail=2) перехватывается в capture-фазе до повторного выбора команды: первый click штатно выбирает команду и заменяет SVG. Dblclick служит запасным событием для фона; после приближения до 100% повторное событие ничего не меняет. Кнопки состава, ссылки, клавиатурные и одиночные клики не перехватываются. Точка клика помещается в центр в пределах прокрутки; кнопки масштаба сохраняют центр. Wheel-обработчиков зума нет.

`enableDiagramPinchZoom` в `pinch.ts` подключён к тому же контейнеру перед двойным кликом. Непассивные `touchstart`/`touchmove` перехватывают только жест с двумя касаниями, начавшимися внутри диаграммы. Расстояние пальцев задаёт плавный масштаб 10–200%; предыдущая середина переносится к текущей через аргумент `destination` у `zoomDiagram`/`zoomScroll`. Начало жеста закрывает карточку; SVG не заменяется. Отпускание, отмена, третий палец или неотменяемое событие прекращают масштабирование; оставшееся касание блокируется до конца жеста. Последующий click подавляется в capture-фазе, клавиатурный click сохраняется. Одиночная прокрутка/нажатия и браузерный зум вне диаграммы не перехватываются. Основа API: [W3C Touch Events](https://www.w3.org/TR/touch-events/).

`main.ts` хранит масштаб числом, обновляет процент и сохранённую прокрутку общей таблицы. `stepZoomScale` выбирает ближайший стандартный уровень в направлении кнопки, включая произвольное значение после жеста; процент возвращает ровно 100%. Закреплённые годы используют тот же transform.

`team-info-position.ts` ограничивает карточку visual viewport. На десктопе размещает относительно кнопки, при нехватке места сбоку выбирает низ/верх. На телефоне `teamInfoSize` задаёт ширину видимой области с полями по 12 px и высоту до 65%; `teamInfoPosition` закрепляет карточку снизу, учитывая нижний отступ из CSS и безопасную область устройства. `team-info.ts` обновляет положение при мобильной прокрутке и событиях `visualViewport.scroll/resize`, компенсирует масштаб карточки обратным transform. При отсутствии API использует размеры окна. Внешнее закрытие работает по `click`, поэтому начало pan или нативного зума страницы не закрывает карточку. Зум самой диаграммы через `pinch.ts` явно закрывает её. Проверка `composedPath()` сохраняет карточку при замене списка внутри обработчика игрока. Десктопная прокрутка и изменение размера по-прежнему закрывают.

События window и visualViewport объединяются через `createFrameUpdate`: не более одного отложенного обновления за кадр, с актуальной геометрией на момент выполнения. Скрытая карточка не ставит обновление в очередь; закрытие отменяет ожидающий кадр. Открытие позиционируется синхронно. Размеры и нижний отступ кэшируются до закрытия/смены содержимого; при изменении доступного размера карточка измеряется заново. На телефоне положение кнопки SVG не читается, а неизменившиеся left/top не записываются.

Связанные узлы с тем же строковым `teamId` получают класс `same-team`, зелёный фон и доступную подпись. Остальные связанные имеют светло-золотистый фон с рамкой в золотистом оттенке; их отдельная кнопка связи получает класс `other-team`, золотисто-коричневый значок и соответствующий hover/раскрытый фон. Активное участие сохраняет тёмно-зелёное выделение; это не добавляет новые связи или узлы.


Режим «Все составы» хранится в `Selection.allRosters`. Renderer и карточки получают общий набор через `getSelectionHistories`/`getSelectionPlayerIds`. В общем режиме цвета стабильны для команды независимо от активного года; переключение между составом одного года и общим набором может изменить палитру. `getSelectionRelations` задаёт выделение; класс `additional` рисует пунктирную рамку только дополнительным участиям. Цвет `same-team` независим от рамки. Активный узел всегда сплошной; доступная подпись дополнительного узла сообщает «связь через другие составы».

`isRosterParticipation` определяет значок людей и интерактивный полный состав конкретного года для всех показанных участий выбранной команды в общем режиме. Внешняя карточка остаётся информационной, учитывает фильтр и подписана «Из составов …». Открытие исторического состава не меняет активное участие. Кнопка активного состава доступна в общей таблице и при фильтре игрока другого года, даже если активное участие не входит в его цепочку. В компактном режиме по-прежнему показаны только участия цепочек; активный год без участия выбранного игрока может быть скрыт.

Каждая строка карточки содержит отдельную ссылку «ID …» на профиль игрока рейтинга в новой вкладке (`noopener noreferrer`), рядом с кнопкой имени или информационным именем карточки связи. Ссылка не вызывает переключение фильтра.
