# flow-ii

Статический сайт независимых историй N ежегодных турниров с общим интерфейсом. Реализованы M1–M6, модель версии 1, реальные JSON, SVG-диаграмма и карточки исторического состава. 6 октября 2026 года публикация flow-ii включена по поручению пользователя: репозиторий публичный, GitHub Pages использует Actions, push в main публикует обе серии. Результаты — в [проверке публикации flow-ii](docs/reports/2026-10-06-flow-ii-publication.md). Карта действующих и исторических документов — [docs/README.md](docs/README.md).

## Запуск и проверки

Требуется Node.js 22.12+ (либо 20.19+), npm. Проверено на Node.js 25.9.0 и npm 11.12.1.

```sh
npm ci
npm run dev
npm test
npm run typecheck
npm run build
npm run preview
```

Vite использует один исходный `index.html` и выводит адрес локального приложения в терминале (обычно http://127.0.0.1:5173). `typecheck` проверяет TypeScript; `build` повторяет проверку и создаёт статический сайт в `dist/`; `preview` показывает сборку (обычно порт 4173). `npm test` компилирует модель и вычисления в `.test-build/`, запускает встроенный `node:test`: цепочки, связи, составы, порядок, диапазон, начальный выбор и различение имён. Дополнительный тестовый фреймворк не требуется.

Для доступа с телефона в той же локальной сети запустите `npm run dev -- --host 0.0.0.0 --port 5173 --strictPort` и откройте сетевой адрес из вывода Vite с путём `/flow-ii/chr/` или `/flow-ii/studchr/`.

## Интерфейс

Изначально выбрана лучшая команда последнего года, выделены цепочки всего её состава. Нажатие на команду выбирает её исторический состав. Кнопка людей у активной команды открывает карточку с названием команды, годом, отдельной строкой места и всеми игроками. Название проведения сохраняется в JSON; отдельной строки проведения и числа игроков в карточке нет. Место также доступно в полной подписи узла. Дополнительной кнопки состава и подписи команды сверху нет.

Имя переключает фильтр игрока: выделяет его цепочку, повторное нажатие возвращает весь состав. Активное имя отмечено крестиком и aria-pressed. Карточка остаётся открытой, фокус сохраняется на имени. Фильтр с крестиком расположен рядом с периодом и «Компактно»; его удаление также возвращает все цепочки и фокусирует «Компактно». Отдельной кнопки «Весь состав» нет. Игроки показаны как «Фамилия И.»; рядом с каждым именем в карточках состава и связи показана отдельная ссылка «ID …» на `https://rating.chgk.info/players/{id}` в новой вкладке. Нажатие имени переключает фильтр, ссылка ведёт на профиль. Совпадающие подписи различаются по ID; доступная подпись кнопки имени также сохраняет ID при совпадении имён. Маркеры цветов сохранены.

Связанные участия с тем же строковым ID команды, что у активного, выделены зелёным фоном. Остальные связанные участия — мягким светло-золотистым фоном с рамкой в золотистом оттенке. Активная команда остаётся тёмно-зелёной; совпадение названий не задаёт выделение.

«Все составы» — отдельный выключенный по умолчанию переключатель рядом с «Компактно». Он объединяет уникальных игроков всех участий выбранной команды по `teamId` и показывает их полные истории, включая другие команды. Переименования сохраняют общий набор; одинаковые названия разных ID его не расширяют. Выбор другого года той же команды сохраняет набор, выбор другой команды перестраивает его; режим сохраняется, фильтр игрока сбрасывается при выборе участия, как прежде. Период ограничивает только диаграмму, компактность независима. При выключении режима фильтр сохраняется, если игрок есть в активном составе, иначе снимается.

В общем режиме у всех показанных участий выбранной команды кнопка людей открывает полный состав конкретного года с выбором игрока. Внешняя карточка связи содержит только игроков данного участия из исторического набора, с учётом фильтра, и подпись «Из составов „Выбранная команда“:». Открытие карточки другого года не меняет активное участие. Цвета линий и маркеров стабильны внутри общего набора одной команды, независимо от активного года и фильтра.

Пунктирная рамка отмечает дополнительные участия, появившиеся только благодаря игрокам других составов: в них нет ни одного игрока состава активного года. Участия обеих групп имеют сплошную рамку. Это правило сохраняется при фильтре игрока. Зелёный/золотистый цвет продолжает обозначать принадлежность команды; активное участие тёмно-зелёное со сплошной рамкой. Пунктир линий по-прежнему означает пропуск проведения игроком.

Кнопка цепочки у связанного участия показывает информационный список игроков выбранных цепочек и подпись источника состава. Карточка открывается только нажатием: на десктопе рядом с кнопкой команды, на телефоне — снизу видимой области экрана. На телефоне ширина занимает экран с полями по 12 px, высота ограничена 65% видимой области, нижний отступ учитывает безопасную область устройства. Карточка учитывает нативный зум и остаётся обычного экранного размера. Прокрутка диаграммы/страницы и перемещение увеличенного экрана на телефоне сохраняют панель у нижнего края. Крестик, Escape, повторное нажатие, отдельное нажатие вне карточки и смена диапазона/режима закрывают её; начало перетаскивания или pinch не закрывает. Изменение только высоты мобильного окна сохраняет карточку; смена ширины закрывает. На десктопе прокрутка диаграммы/страницы и изменение размера закрывают карточку. После выбора игрока карточка связана с новой кнопкой того же участия в SVG; Escape возвращает фокус на кнопку людей.

Диапазон сохраняет выбор и фильтр, меняет только диаграмму и не создаёт связей. Чтобы открыть состав скрытого участия, верните его год в период и найдите выбранную команду на диаграмме. Полные истории вычисляются из всех фактов; текстовые списки и нижняя панель удалены. Новые годы слева, пунктир означает пропуск проведения в полном наборе. Ссылки годов открывают турниры рейтинга.

Узлы команд исключены из Tab; произвольная команда выбирается мышью или касанием. Ссылки годов, кнопки состава и управление доступны с клавиатуры; диаграмма прокручивается стрелками. Строка годов закреплена при вертикальной прокрутке и синхронна с колонками по горизонтали и масштабу. «Компактно» уплотняет участия выбранных цепочек, возврат восстанавливает прокрутку общей таблицы. Страница занимает 100dvh, диаграмма — оставшуюся высоту после статистики, управления и футера с прокруткой по обеим осям, без измерений в JavaScript. При отсутствии участий в диапазоне показано сообщение.

Диаграмму можно тянуть левой кнопкой мыши в любом направлении, в том числе за название команды. Перетаскивание использует обычную прокрутку контейнера без перерисовки SVG; движение от 5 px отделяется от клика и не меняет выбор. На тачпаде и телефоне сохраняются нативные жесты, также доступны колесо и полосы прокрутки.

## Добавление отдельного турнира

Серии в локальной сборке: ЧР — `/flow-ii/chr/`; СтудЧР — `/flow-ii/studchr/` (26 проведений за 2001–2026, 671 команда, 3813 игроков, 1194 участия). Для обновления СтудЧР: `npm run convert:xlsx -- studchr`. Предоставленные XLSX лежат непосредственно в `data/tournaments/studchr/`; пути закреплены в её `sources.json`.

Реестр `data/tournaments.json` используется при сборке и преобразовании. В общий JS включаются только публичные настройки маршрутов: `slug`, `name` и `history`; списки XLSX туда не попадают. У каждого турнира свой `slug`, отображаемое `name`, `sources` относительно корня проекта и `history` относительно `public/`. `defaultTournament` определяет перенаправление с корня и преобразование без аргументов. Ключ серии не связан с `editions[].tournamentId`: последний относится к ежегодному проведению рейтинга.

Добавьте в массив `tournaments` запись (название и ключ условные):

```json
{
  "slug": "second",
  "name": "Второй турнир",
  "sources": "data/tournaments/second/sources.json",
  "history": "data/second/history.json"
}
```

1. Выберите уникальный ключ каталога из строчных латинских букв, цифр и дефисов; `assets` и `data` заняты статическими ресурсами.
2. Положите XLSX в `data/tournaments/second/source/`, создайте `data/tournaments/second/sources.json` в прежнем формате: `file: "source/…xlsx"`, название проведения, необязательный лист.
3. Выполните `npm run convert:xlsx -- second`, проверки и `npm run build`. Страница `/flow-ii/second/` создаётся автоматически. Код диаграммы и HTML копировать не нужно.
4. Проверьте страницу и включите в публикацию реестр, список источников и готовый JSON; XLSX остаются локальными.

Каждая страница загружает только свой JSON. Совпадение ID между турнирами не связывает истории; схема версии 1 сохраняется отдельно для каждого набора, одно проведение на год внутри каждой серии. Меню и ссылки между турнирами отсутствуют. Страницы и JSON публикуются в одной сборке; общий код интерфейса применяется ко всем турнирам.

Vite собирает один `index.html` с общими JS/CSS. Завершающий шаг в `scripts/site-pages.ts` копирует готовый HTML в каталоги турниров, подставляет их заголовки, поправляет относительные URL ресурсов и заменяет корень лёгкой страницей перенаправления. JS выбирает турнир по пути и запрашивает только его JSON; отдельные настройки в HTML не нужны. После изменения реестра перезапустите `npm run dev`; изменения HTML работают через обычный Vite. Удаление записи удаляет страницу из следующей сборки; чтобы убрать её данные из публикации, также удалите соответствующий готовый JSON из `public/`. Сборка и CI не читают XLSX и не запускают импорт.

## Подготовка и обновление данных

Положите все ежегодные таблицы в `data/tournaments/chr/source/` (в корне проекта), без подпапок по годам. Формат имени — `tournament-with-players-<tournamentId>-<year>.xlsx`, например `tournament-with-players-1710-2011.xlsx`: `1710` — ID турнира в источнике, `2011` — год.

XLSX хранятся локально и исключены из Git, включая прежнюю историю. В клоне репозитория их нет: для пересоздания JSON нужно отдельно получить исходные выгрузки и положить их в `data/tournaments/chr/source/`. Для запуска, тестов и сборки сайта достаточно уже включённого в репозиторий готового JSON; повторное преобразование не требуется. Список источников и скрипт остаются в Git.

Преобразователь извлекает ID источника и год из имени файла; строковый ID сохраняется в `editions[].tournamentId` для ссылки года на rating.chgk.info. Названия проведений задаются отдельно в `data/tournaments/chr/sources.json`; год в нём не дублируется. Пути разрешаются относительно каталога списка. Пример (название условное):

```json
{
  "editions": [
    {
      "file": "source/tournament-with-players-1710-2011.xlsx",
      "sheet": "Worksheet",
      "name": "Название проведения — 2011"
    }
  ]
}
```

Если `sheet` отсутствует, читается первый лист. Порядок записей произвольный. Подготовка готового JSON:

```sh
npm run convert:xlsx
```

JSON пересоздаётся только при явном запуске команды преобразования, по необходимости. `npm run dev`, `npm run build` и открытие сайта не запускают преобразование; они используют уже готовый JSON. Команда компилирует `scripts/convert-xlsx.ts` и пересоздаёт `public/data/chr/history.json` из всего списка. JSON записывается одной строкой без форматирующих отступов, с завершающим переносом; схема и все данные сохраняются. Для выбранного турнира: `npm run convert:xlsx -- <slug>`; без аргументов используется `defaultTournament` из реестра. Пересоздаётся только его JSON; XLSX остальных турниров не требуются. Для другого списка и выходного пути: `npm run convert:xlsx -- /путь/sources.json /путь/history.json`. ExcelJS — зависимость разработки только для Node, она не входит в браузерную сборку. Транзитивная `uuid` закреплена через overrides на исправленной ветке 11; чтение и запись проверены тестом.

Для нового года добавьте XLSX в `data/tournaments/chr/source/` и запись с названием в список, запустите `npm run convert:xlsx`, затем `npm run build`. Для исправления существующего года замените его XLSX или название и выполните те же команды. Старый JSON не используется как вход и не дополняется. Годы без выгрузок не создаются; город и флаг игнорируются, все игроки сохраняются, имена записываются как «Фамилия И.», отчество игнорируется. Ошибка чтения или записи выводится в терминал, команда возвращает ненулевой код. XLSX и список находятся вне `public/`.

После успешного преобразования XLSX можно удалить с рабочего компьютера: готовый JSON, сайт и сборка от этого не меняются. Для следующего запуска нужны все XLSX из `data/tournaments/chr/sources.json`, включая неизменённые годы; одного исправленного или нового файла недостаточно. Сохраняйте полный набор отдельно и возвращайте его перед преобразованием. Для обновления локальной сборки выполните проверки и сборку. Коммит и push выполняются в пределах поручения; push в main автоматически публикует сайт.

Сохраняйте ID команды и игрока из источника: переименование не создаёт новый ID, совпадение имён не объединяет разные ID. Историческое название команды и состав сохраняются в участии каждого года; справочные имена берутся из последнего известного проведения. Исходник предполагает одну команду игрока на проведение; дополнительные проверки или подтверждения данных не нужны.

В `data/tournaments/chr/sources.json` перечислены все предоставленные XLSX; названия проведений заданы по согласованному шаблону «ЧР — <год>». В `data/tournaments/chr/source/` есть 21 реальный файл: 2001–2019, 2025–2026. Само добавление XLSX не обновляет сайт.

Отчёты в `docs/reports/` текстовые. Новые скриншоты в репозиторий не сохраняются; визуальные проверки выполняются без постоянных изображений.

## Код и данные

- `src/main.ts`, `src/style.css`, `index.html` — страница, диапазон, состояние выбора и загрузки.
- `src/model/types.ts`, `src/model/load-history.ts`, `src/model/tournament-page.ts` — модель, выбор серии по пути и загрузка единственного JSON.
- `src/history/index.ts` — индексы, полные цепочки и проекция диапазона ([API](src/history/README.md)); `src/history/selection.ts` — выбор, доступные подписи и контрастные цвета по ID внутри полного выбранного набора игроков (сохраняются при выборе игрока и диапазона).
- `src/diagram/index.ts`, `src/diagram/team-info.ts` — SVG-диаграмма, карточка состава и выбор игрока.
- `public/data/chr/history.json` — готовая реальная история версии 1. Сайт не импортирует XLSX и не валидирует факты.

[Контракт данных](docs/data-contract.md) определяет строковые ID, поля проведения, историческое название/состав и дробные места. [Описание примеров](data/fixtures/README.md) и [сценарии](data/fixtures/history-scenarios.json) задают ожидаемые цепочки M2–M3. Набор сохранён в `data/fixtures/demo-history.json`: 6 условных лет, 90 команд, 574 игрока, 540 участий. Тесты используют эту копию независимо от обновления рабочего JSON. Рабочий JSON содержит 21 проведение, 420 команд, 2679 игроков и 1324 участия; демонстрационные подписи удалены.

Базовый путь сборки — `/flow-ii/`; GitHub Pages включён, публикация выполняется через Actions при push в main либо вручную. XLSX и скрипт не входят в браузерное приложение. `npm run typecheck` проверяет также скрипт; `npm test` компилирует его в `.script-build/` и проверяет преобразование корректного XLSX с известным ожидаемым JSON.

## Индексация

HTML всех серий и отдельно генерируемый корневой редирект содержат в исходном `<head>` ровно один `<meta name="robots" content="noindex, nofollow">`. Правило доступно до выполнения JavaScript. На текущем GitHub Pages нельзя задать собственный HTTP-заголовок `X-Robots-Tag`; JSON не имеет собственного noindex, и метатег HTML на него не распространяется. `robots.txt` в подпапке `/flow-ii/` не применяется: поисковики читают его из корня хоста. Такой файл в проект не добавляется. Правило исключения HTML действует для соблюдающих его поисковиков после обработки страницы и не закрывает прямой доступ. Проверены локальная сборка и публичные HTML flow-ii: метатег присутствует в корне и обеих сериях. [План и границы настройки](docs/plans/2026-10-06-search-indexing.md).

## Публикация — M6 (завершён)

`vite.config.ts` задаёт base `/flow-ii/`; Vite имеет одну HTML-точку входа; после сборки готовая страница копируется в каталоги турниров. Общий JS выбирает адрес JSON по пути страницы. Ресурсы работают с обычным и относительным base. В `.github/workflows/pages.yml` включены push в main и ручной запуск из Actions, шаги `npm ci`, `npm test`, `npm run build` и публикация только `dist/`. Успех конкретной публикации подтверждается запуском workflow для отправленного SHA и проверкой публичного сайта. Преобразование XLSX в CI не предусмотрено.

Для обновления данных ЧР восстановите все её XLSX и выполните:

```sh
npm run convert:xlsx -- chr
npm test
npm run typecheck
npm run build
git add public/data/chr/history.json data/tournaments/chr/sources.json
git commit -m "Обновить историю турнира"
git push origin main
```

Для СтудЧР используйте `npm run convert:xlsx -- studchr` и включите в коммит `public/data/studchr/history.json` и изменения `data/tournaments/studchr/sources.json`. При добавлении серии включите также `data/tournaments.json`. Преобразование нужно только при изменении данных; для правок интерфейса достаточно проверок, сборки и коммита затронутых файлов. Push в `main` автоматически публикует обе серии; ручной запуск доступен в Actions → Publish GitHub Pages → Run workflow.

Если обычный Git ещё не авторизован, установленный GitHub CLI может использовать сохранённую для этого проекта запись Связки ключей macOS:

```sh
GH_TOKEN="$(security find-generic-password -a sunduev -s chr-flow-github -w)" \
  git -c credential.helper= -c 'credential.helper=!gh auth git-credential' push origin main
```

Этот вариант использует токен только для команды и не записывает его в репозиторий. Запись `chr-flow-github` даёт доступ к новому `sunduev/flow-ii` и используется без сохранения токена в файлы; в другом окружении используйте свою авторизацию Git с доступом на запись в репозиторий.

После публикующего push найдите запуск `Publish GitHub Pages` именно для отправленного SHA и дождитесь успешного завершения. Проверьте корневой редирект, страницы обеих серий и сравните публичные JSON `/flow-ii/data/chr/history.json` и `/flow-ii/data/studchr/history.json` с соответствующими файлами в `public/data/`. Сборка использует готовый JSON и не требует XLSX. Временные тестовые данные не должны заменять реальную историю.

В приёмке M6 подтверждены gzip для JSON, JS и CSS, `Cache-Control: max-age=600` и ответы 304 на условные повторные запросы. 5 октября `max-age=600` повторно подтверждён для обеих страниц и JSON. После успешной публикации свежий кеш может сохранять прежнюю историю около 10 минут. По истечении срока обычное открытие/обновление страницы загружает новые данные без очистки кеша; уже открытая страница сама данные не обновляет. Фактический эксперимент и ограничения CDN описаны в [отчёте M6](docs/reports/M6.md).

## Воспроизведение приёмки M5

Для локального стенда соберите сайт с относительным base: `npm run build -- --base=./`, затем запустите `node scripts/serve-quality.mjs` (необязательный аргумент — порт, по умолчанию 4175). Откройте `http://127.0.0.1:4175/full/chr/` для полного рабочего набора, `/empty/chr/` для пустого и `/error/chr/` для HTTP 503. Стенд читает `dist/`, отдаёт тестовые ответы только локально и не меняет рабочий JSON. Префиксы — маршруты стенда. Для публикации вернитесь к обычной `npm run build` с base `/flow-ii/`.

Отчёт M5 сохраняет приёмку интерфейса 2 октября 2026 года, до последующих изменений UI.
