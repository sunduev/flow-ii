# flow-ii

Статический сайт истории ежегодных турниров: места команд по годам, исторические составы и цепочки игроков. Каждая серия имеет отдельные данные и страницу с общим интерфейсом.

Открыть сайт: [ЧР](https://sunduev.github.io/flow-ii/chr/) · [СтудЧР](https://sunduev.github.io/flow-ii/studchr/). Корень сайта перенаправляет на ЧР.

## Запуск и проверки

Требуется Node.js 22.12+ (либо 20.19+) и npm. Исходные XLSX для запуска, тестов и сборки не нужны: готовые JSON включены в репозиторий.

```sh
npm ci
npm run dev
```

Откройте адрес из вывода Vite с путём `/flow-ii/chr/` или `/flow-ii/studchr/` (обычно `http://127.0.0.1:5173/flow-ii/chr/`). Для доступа с телефона в той же локальной сети:

```sh
npm run dev -- --host 0.0.0.0 --port 5173 --strictPort
```

Используйте сетевой адрес из вывода Vite с тем же путём серии.

```sh
npm test
npm run typecheck
npm run build
npm run preview
```

`npm test` проверяет вычисление истории, выбор и преобразование XLSX на примерах с известным результатом. `typecheck` проверяет TypeScript приложения и скриптов. `build` повторяет проверку типов и создаёт статический сайт в `dist/`; `preview` показывает сборку, обычно на порту 4173.

## Интерфейс

Годы идут от новых к старым, самый новый — слева; команды внутри года упорядочены по месту. Изначально выбрана лучшая команда последнего года. Нажатие на команду выделяет полные цепочки игроков её состава за все известные годы этой серии. Пунктир линии означает пропуск промежуточного проведения из полного набора; календарный разрыв сам по себе не создаёт пунктир.

Кнопка людей открывает исторический состав: название команды, год, место и всех игроков. Нажатие имени выделяет цепочку одного игрока; повторное нажатие или крестик фильтра возвращает весь набор. Игроки показаны как «Фамилия И.», рядом — отдельная ссылка «ID …» на профиль рейтинга. Совпадение имён не объединяет игроков.

«Все составы» объединяет игроков всех известных составов выбранной команды по её ID и показывает их истории, включая другие команды. Кнопки людей у её участий открывают состав конкретного года, не меняя активное участие. Кнопка цепочки у другого связанного участия показывает игроков из выбранных цепочек. При выключении режима фильтр сохраняется, если игрок входит в активный состав.

Активное участие тёмно-зелёное; другие участия той же команды зелёные, остальных связанных команд — золотистые. Пунктирная рамка в режиме «Все составы» отмечает участия, появившиеся только благодаря игрокам других составов: в них нет игроков состава активного года.

Диапазон лет меняет только диаграмму, сохраняет выбор и фильтр игрока и закрывает карточку. Для просмотра состава скрытого участия верните его год в период. «Компактно» оставляет только участия выбранных цепочек и уплотняет строки.

Масштаб меняется кнопками «− / процент / +» от 10% до 200%; нажатие процента возвращает 100%. На телефоне растяжение/сжатие двумя пальцами внутри диаграммы плавно меняет её масштаб вокруг середины жеста; перемещение двух пальцев сдвигает диаграмму. Процент обновляется, кнопки переходят к ближайшему меньшему/большему стандартному уровню. Жест сохраняет выбор и фильтр игрока, закрывает карточку состава и не вызывает случайного выбора команды после отпускания пальцев. Один палец прокручивает диаграмму и выбирает команды обычным касанием; вне диаграммы сохраняется браузерный зум страницы. При масштабе меньше 100% двойной клик приближает область до 100%. На компьютере диаграмму можно прокручивать или тянуть левой кнопкой мыши; тачпад сохраняет нативную прокрутку. Строка годов закреплена при вертикальной прокрутке.

На компьютере карточка открывается рядом с кнопкой, на телефоне — снизу экрана. Крестик, Escape, повторное нажатие кнопки или отдельное нажатие вне карточки закрывают её. Управление, ссылки годов, кнопки состава и игроки доступны с клавиатуры; Escape возвращает фокус на кнопку состава. Произвольные команды выбираются мышью или касанием, их узлы исключены из Tab.

## Подготовка и обновление данных

Реестр серий — `data/tournaments.json`. Для каждой серии он задаёт ключ `slug`, название `name`, путь `sources` относительно корня проекта и путь `history` относительно `public/`. `defaultTournament` определяет перенаправление с корня и серию для преобразования без аргументов.

XLSX хранятся локально и исключены из Git. Для пересоздания JSON нужны **все файлы выбранной серии** из её `sources.json`, включая неизменённые годы. Сохраняйте полный набор отдельно: существующий JSON не используется как вход преобразователя.

Для ЧР исходники лежат в `data/tournaments/chr/source/`, список — в `data/tournaments/chr/sources.json`. Для СтудЧР список — `data/tournaments/studchr/sources.json`, пути XLSX заданы относительно его каталога; текущие исходники лежат непосредственно в `data/tournaments/studchr/`.

Формат имени XLSX — `tournament-with-players-<tournamentId>-<year>.xlsx`. Например, `tournament-with-players-1710-2011.xlsx` задаёт ID проведения в рейтинге `1710` и год `2011`. Название задаётся в списке источников:

```json
{
  "editions": [
    {
      "file": "source/tournament-with-players-1710-2011.xlsx",
      "sheet": "Worksheet",
      "name": "Название проведения — 2011"
    }
  ]
}
```

Если `sheet` отсутствует, читается первый лист. Порядок записей произвольный.

Для нового года добавьте XLSX и запись в список; для исправления существующего замените его XLSX или метаданные. Затем выполните:

```sh
npm run convert:xlsx -- chr
npm test
npm run typecheck
npm run build
```

Для СтудЧР используйте `npm run convert:xlsx -- studchr`. Команда пересоздаёт только JSON выбранной серии в `public/data/<slug>/history.json`. Без аргументов используется `defaultTournament`; для отдельного списка и выходного пути доступно `npm run convert:xlsx -- /путь/sources.json /путь/history.json`.

Запуск приложения и сборка используют готовый JSON и не запускают преобразование. Скрипт и ExcelJS работают только в Node и не входят в браузерное приложение. Ошибка чтения или записи выводится в терминал, команда возвращает ненулевой код.

Сохраняйте ID команд и игроков из источника: переименование не создаёт новый ID, совпадение имён не объединяет разные ID. Название команды и состав относятся к конкретному участию; справочные имена берутся из последнего известного проведения. Годы без выгрузок не добавляются, город и флаг игнорируются, все игроки сохраняются. Точная схема и правила преобразования — в [контракте данных](docs/data-contract.md).

## Добавление отдельного турнира

Добавьте в массив `tournaments` файла `data/tournaments.json` запись:

```json
{
  "slug": "second",
  "name": "Второй турнир",
  "sources": "data/tournaments/second/sources.json",
  "history": "data/second/history.json"
}
```

1. Выберите уникальный ключ из строчных латинских букв, цифр и дефисов; `assets` и `data` заняты ресурсами.
2. Положите XLSX в `data/tournaments/second/source/` и создайте `data/tournaments/second/sources.json` в формате выше.
3. Выполните `npm run convert:xlsx -- second`, проверки и `npm run build`. Страница `/flow-ii/second/` создаётся автоматически.
4. Проверьте страницу и включите в публикацию реестр, список источников и готовый JSON. XLSX остаются локальными.

После изменения реестра перезапустите `npm run dev`. Каждая страница загружает только свой JSON; ID разных серий независимы, связей и навигации между сериями нет. Общий интерфейс применяется ко всем турнирам. Удаление записи убирает страницу из следующей сборки; для удаления её данных также удалите соответствующий JSON из `public/`.

## Публикация

Базовый путь — `/flow-ii/`. Workflow [Publish GitHub Pages](.github/workflows/pages.yml) запускается при push в `main` либо вручную через Actions → Publish GitHub Pages → Run workflow. Он устанавливает зависимости, выполняет тесты и сборку и публикует только `dist/`. Преобразование XLSX в CI не запускается.

После локальных проверок включите в коммит изменённые файлы. Для обновления ЧР:

```sh
git add public/data/chr/history.json data/tournaments/chr/sources.json
git commit -m "Обновить историю турнира"
git push origin main
```

Для другой серии замените `chr` её ключом; при добавлении серии включите также `data/tournaments.json`. Для правок интерфейса преобразование данных не требуется. Коммит и push выполняются в пределах поручения; push в `main` публикует все серии. Порядок использования сохранённого доступа на рабочем Mac описан в [AGENTS.md](AGENTS.md#авторизация-и-публикация-github-pages).

После push дождитесь успешного workflow именно для отправленного SHA. Проверьте корневой редирект и страницы серий, сравните публичные JSON `/flow-ii/data/<slug>/history.json` с файлами `public/data/<slug>/history.json`.

Кеш GitHub Pages может сохранять прежние данные около 10 минут после публикации. Уже открытая страница автоматически данные не перечитывает; для загрузки обновления её нужно обновить.

## Индексация

HTML страниц и корневого редиректа содержит `<meta name="robots" content="noindex, nofollow">`. Это правило действует для соблюдающих его поисковиков и не закрывает прямой доступ. На JSON метатег не распространяется. `robots.txt` в подпапке `/flow-ii/` не применяется, поэтому такой файл не добавляется.

## Проверка интерфейса

Для локального стенда с рабочими данными, пустым набором и ошибкой загрузки:

```sh
npm run build -- --base=./
node scripts/serve-quality.mjs
```

Откройте `http://127.0.0.1:4175/full/chr/`, `/empty/chr/` или `/error/chr/`. Стенд читает `dist/` и не меняет рабочий JSON; необязательный аргумент скрипта задаёт порт. Перед публикацией вернитесь к обычной `npm run build`.

Основной сценарий: выберите ЛКИ 2013, откройте состав, выберите «Руссо М.» (ID 27403), затем диапазон 2025–2026. Выбор команды и фильтр должны сохраниться, карточка — закрыться. Верните 2013 в период и снова откройте состав. Проверьте снятие фильтра, «Компактно», «Все составы», масштаб и прокрутку. «Первая сборная» 2026 должна показывать место 6,5 и восемь игроков. Повторите на размерах 1280×900 и 390×844; клавиатурой проверьте управление, ссылки годов, кнопки состава, игроков и Escape.

Стенд публикует измерения в `document.documentElement.dataset.qaMetrics`, адреса fetch-запросов — в `document.documentElement.dataset.qaRequests`. Страница должна запрашивать только JSON своей серии. Измеритель не входит в production-сборку.

## Структура и документация

- `src/main.ts`, `src/style.css`, `index.html` — страница, управление и состояние загрузки.
- `src/model/` — типы, выбор серии по пути и загрузка JSON.
- `src/history/` — индексы, полные цепочки, проекция диапазона и выбор ([API](src/history/README.md)).
- `src/diagram/` — SVG-диаграмма и карточки ([описание](src/diagram/README.md)).
- `scripts/convert-xlsx.ts` — подготовка данных; `scripts/site-pages.ts` — создание страниц серий из общего HTML после сборки Vite.
- `public/data/<slug>/history.json` — готовые реальные данные; `data/fixtures/` — отдельные [тестовые примеры](data/fixtures/README.md).

[Карта документации](docs/README.md) содержит ссылки на требования, контракт, планы и отчёты проекта.
