# План реализации сайта с историей ежегодного турнира

Статус: черновик плана. Дата: 2 октября 2026 года.

Исторический документ. Актуальные требования находятся в [plan.md](plan.md), задания — в `milestones/`, процесс работы — в [AGENTS.md](../AGENTS.md). По уточнению пользователя отдельный скрипт преобразует XLSX и сохраняет готовый JSON; сайт только читает его. Данные считаются корректными и полными, валидация не требуется. Детали — в [контракте данных](data-contract.md). Черновик приведён к этим ограничениям; для реализации использовать актуальный план и задания.

## Цель и границы

Создать статический сайт для одного ежегодного турнира. Он показывает места команд по годам, исторические составы и полную цепочку команд каждого игрока в рамках этого турнира.

Пользователь предоставляет XLSX каждого проведения и его год и название. Формат образца уже изучен. Отдельный `scripts/convert-xlsx.ts` по списку `data/sources.json` создаёт `public/data/tournament-history.json`; это целевые пути при реализации. Сайт читает готовый JSON, функций импорта и проверки данных на сайте нет.

Дополнительные продуктовые функции не планируются: не добавляем другие турниры, личные кабинеты, редактирование данных через сайт или отдельные страницы игроков.

## Согласованное направление интерфейса

Необязательный макет для идей, а не утверждённый целевой дизайн (улучшения допустимы):
[Макет](references/tournament-history.html).

- Годы расположены колонками слева направо, от новых к старым; самый новый год слева.
- В каждой колонке команды упорядочены по занятому месту. Место и название подписаны явно.
- Фоновые связи приглушены. Нажатие на команду выделяет полные цепочки всех игроков её состава, включая годы до и после выбранного участия.
- Ниже диаграммы открываются название команды, год, место и состав именно на выбранном турнире.
- Нажатие на игрока выделяет только его цепочку. Кнопка «Весь состав» возвращает цепочки всех игроков выбранного состава.
- В панели есть текстовая последовательность «год → команда» для каждого выделенного игрока. Она помогает читать пересекающиеся линии и сохраняет историю доступной на телефоне.
- Для длинной истории предусмотрены горизонтальная прокрутка диаграммы и выбор диапазона лет. Панель продолжает показывать полную историю игрока независимо от видимого диапазона.

Начальное состояние: все годы, выбран победитель последнего доступного турнира, показаны цепочки всего его состава.

## Техническое решение

Предлагаемый стек: **Vite + TypeScript + SVG + `d3-scale` и `d3-shape`**, обычный CSS. React для согласованного объёма не требуется.

- Vite отвечает за локальную разработку и сборку статического сайта.
- TypeScript описывает данные и состояние выбора.
- Собственная небольшая функция размещает команды: колонка определяется годом, строка — порядком в результатах.
- D3 рассчитывает шкалы и плавные SVG-линии между известными точками. Автоматическую раскладку Sankey не используем: положение команд должно соответствовать местам.
- Сайт загружает подготовленный JSON из собственных статических файлов. Постоянный сервер и база данных не нужны.
- Целевой вариант размещения — GitHub Pages. Настройку публикации выполним на заключительном этапе.

## Модель данных

Храним исходные факты, а связи и цепочки вычисляем из них. Имена не используем в качестве идентификаторов.

| Сущность | Основные поля |
| --- | --- |
| Проведение турнира | `id`, `year`, `name` |
| Команда | `id`, название для справочника |
| Игрок | `id`, имя |
| Участие команды | `id`, `editionId`, `teamId`, `displayName`, `place`, `playerIds` |

Название и состав в записи участия относятся к конкретному году. Переименование команды с сохранением ID не разрывает её историю. Возвращение игрока в прежнюю команду сохраняется отдельным участием в цепочке.

ID нормализуем в строки. В итоговом JSON сохраняем `schemaVersion: 1`. Формат и преобразование уже закреплены в контракте; данные считаются корректными без отдельного валидатора.

Правила интерпретации:

- Цепочка показывает участия в нашем турнире, а не доказанные даты трансферов или историю участия в других соревнованиях.
- Если между известными участиями есть пропущенные годы, связь обозначается пунктиром. Не назначаем игроку команду на годы без данных.
- Команды с одинаковым местом получают отдельные строки и одинаковую подпись места; внутри равного места используем стабильный порядок по ID.
- Составы считаются полными, статусы полноты не нужны. Сохраняются все игроки и дробные места; город и флаг игнорируются, отчество сохраняется в полном имени.

## Этапы реализации

### 1. Основа проекта и демонстрационные данные

- [ ] Создать проект Vite с TypeScript, базовые команды запуска и сборки.
- [ ] Разделить модель данных, вычисления истории, диаграмму и панель состава.
- [ ] Подготовить небольшой демонстрационный набор: смена команды, сохранение состава, возвращение игрока, переименование команды, пропуск года, равные места.
- [ ] Оформить краткий README с командами запуска.

Результат: проект запускается локально и собирается; разработка интерфейса не зависит от получения таблицы.

### 2. Вычисление истории игроков

- [ ] Построить индексы участий по году, команде и ID игрока.
- [ ] Для каждого игрока получить все известные участия в хронологическом порядке.
- [ ] Вычислить фоновые связи между командами и отдельные цепочки выделенных игроков.
- [ ] Разделить полную историю и её отображение в выбранном диапазоне лет.
- [ ] Проверить вычисления на возвращениях, пропусках, переименованиях и однофамильцах с разными ID.

Результат: выбор состава возвращает полные цепочки его игроков, а не только связи соседних лет или историю одной команды.

### 3. Диаграмма и панель состава

- [ ] Разработать удобное оформление; необязательный макет можно улучшать.
- [ ] Отрисовать годы, места, названия команд и фоновые связи в SVG.
- [ ] Реализовать выбор команды, игрока и возврат к всему составу.
- [ ] Связать выделение диаграммы с составом и текстовыми цепочками.
- [ ] Развести совпадающие выделенные линии небольшими смещениями; цвет игрока сохраняется при переключении между его цепочкой и всем выбранным составом.
- [ ] Добавить диапазон лет и прокрутку длинной диаграммы.
- [ ] Сохранить выбранную команду и игрока при изменении диапазона; скрытые годы остаются в полной текстовой истории.

Результат: интерактивный прототип повторяет согласованное поведение и пригоден для проверки на реальном объёме данных.

### 4. Отдельный скрипт и подключение JSON

- [ ] Выбрать библиотеку чтения XLSX для отдельного скрипта.
- [ ] Написать `scripts/convert-xlsx.ts`: таблицы и метаданные из `data/sources.json` → единый JSON в `public/data/tournament-history.json`.
- [ ] Проверить преобразование корректного примера с известным результатом; валидатор и диагностика данных не нужны.
- [ ] Подключить готовый файл к сайту и проверить отображение.

Результат: реальные данные воспроизводимо преобразуются одной командой и отображаются на сайте.

### 5. Проверка читаемости и качества

- [ ] Проверить диаграмму на полном количестве лет, команд и связей.
- [ ] Проверить длинные названия и имена, пересечения линий и крайние места.
- [ ] Проверить использование на компьютере и телефоне, включая прокрутку и текстовую историю.
- [ ] Сделать выбор команды и игрока доступным с клавиатуры; сохранять видимый фокус и понятные подписи.
- [ ] Написать содержательные тесты преобразования данных и вычисления цепочек.
- [ ] Проверить основной сценарий в браузере: команда → состав → игрок → вся история → весь состав → другая команда.
- [ ] Выполнить проверку TypeScript и сборку. Если реальный объём выявит задержки, оптимизировать вычисления и обновление SVG по результатам замеров.

Результат: сайт корректно работает на реальных данных, подписи читаются, выделение не теряется и полная история доступна.

### 6. Публикация и ежегодное обновление

- [ ] Настроить сборку и пути статических файлов для GitHub Pages.
- [ ] Опубликовать сайт и проверить загруженные данные и основной сценарий по публичному адресу.
- [ ] Описать процедуру обновления: новый XLSX и метаданные → отдельный скрипт → готовый JSON → сборка → публикация.

Результат: сайт доступен по постоянному адресу, очередной год можно добавить без изменения кода интерфейса.

## Критерии готовности

- Все предоставленные годы и результаты отображаются без потери записей.
- Каждая выбранная команда показывает исторически верный состав и место.
- Для каждого игрока выбранного состава доступна вся известная цепочка команд за все годы турнира.
- Пропуски и переименования не создают ложных участий и не разрывают известную историю.
- Сайт работает на компьютере и телефоне и не требует серверного приложения.
- Подготовка данных и ежегодное обновление описаны и воспроизводимы.
