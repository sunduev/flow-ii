# Noindex для текущего сайта на GitHub Pages

Дата: 6 октября 2026 года. Статус: локальные разделы 1–3 выполнены; раздел 4 ожидает отдельного поручения публикации.

## Цель и границы

Задать правила исключения HTML сайта из поисковой выдачи средствами текущего репозитория `sunduev/flow-chr` и GitHub Pages. Сайт остаётся статическим, без авторизации. Размещение — `https://sunduev.github.io/flow-chr/`, production base — `/flow-chr/`.

Задание касается метатегов, доступных настроек индексации и проверки результата. Смена хостинга/домена, новый репозиторий, переписывание истории, изменение данных, удаление результатов через кабинеты поисковиков и настройка другого репозитория в него не входят.

По последней подтверждённой проверке репозиторий приватный, Pages отключён; состояние публикующего workflow отдельно не подтверждено. Выполнение локальной части не требует включения сайта. Commit, push и возобновление публикации выполняются только по отдельному поручению.

## Принятые настройки и ограничения

1. Для всех HTML использовать один метатег в исходном `<head>`:

   ```html
   <meta name="robots" content="noindex, nofollow">
   ```

   `noindex` задаёт исключение страницы из поиска; `nofollow` дополняет его правилом для ссылок. Тег должен присутствовать в HTML ответа до выполнения JavaScript. Отдельные дубли для Google и Яндекса не нужны.
2. На обычном GitHub Pages нет поддерживаемой настройки произвольного HTTP-заголовка ответа `X-Robots-Tag`. Не добавлять `_headers`, `.htaccess`, `meta http-equiv` или настройки заголовков Vite как имитацию такой настройки на Pages. Для JSON отдельный HTTP-noindex в рамках этого размещения остаётся недоступным; метатег HTML на JSON не распространяется.
3. Для этого адреса поисковики читают `https://sunduev.github.io/robots.txt`, а не `/flow-chr/robots.txt`. Корень хоста находится вне данного проекта. Не создавать `public/robots.txt` как действующую защиту сайта в подпапке и не менять корневой сайт пользователя в рамках задания.
4. HTML и необходимые ресурсы должны быть доступны поисковику, чтобы он прочитал `noindex`. Не сочетать запрет обхода HTML через `Disallow` с ожиданием обработки его метатега. Директива `Noindex` в robots.txt не заменяет метатег.

Правила рассчитаны на поисковики, которые их соблюдают. Они не закрывают прямой доступ, не управляют индексированием страниц GitHub и не отзывают ранее скачанные копии. Уже известные страницы исчезают из выдачи после обработки изменений поисковиком, а не сразу после сборки.

Основания: [Google: исключение через noindex](https://developers.google.com/search/docs/crawling-indexing/block-indexing), [Google: robots-метатеги и HTTP-заголовки](https://developers.google.com/search/docs/crawling-indexing/robots-meta-tag), [Google: расположение robots.txt](https://developers.google.com/crawling/docs/robots-txt/create-robots-txt), [Яндекс: запрет индексирования](https://yandex.ru/support/webmaster/ru/robot-workings/unhelpful), [ответ команды GitHub об отсутствии пользовательских заголовков Pages](https://github.com/orgs/community/discussions/54257).

## Файлы и исходное поведение

Перед реализацией прочитать `AGENTS.md`, `docs/plan.md`, `docs/data-contract.md`, README, `milestones/M6-release.md` и текущий отчёт очистки `docs/reports/2026-10-06-player-name-cleanup.md`. Проверить `git status --short`; сохранить чужие изменения.

| Файл | Действие |
| --- | --- |
| `index.html` | Добавить общий robots-метатег в `<head>` |
| `scripts/site-pages.ts` | Добавить такой же тег в отдельно генерируемый корневой редирект |
| `tests/tournaments.test.mjs` | При расширении существующих проверок подтвердить сохранение тега при раскладке HTML и его наличие в редиректе |
| `README.md`, `docs/plan.md` | Кратко описать настройку, охват HTML и ограничение для JSON на Pages |
| `docs/reports/2026-10-06-search-indexing.md` | После реализации сохранить текстовый отчёт с фактическими проверками |

Реестр — `data/tournaments.json`. Vite собирает один HTML, затем `scripts/site-pages.ts` копирует его в каталоги всех серий и заменяет корень отдельным HTML-редиректом. Поэтому изменение только исходного `index.html` не охватит корневую страницу. Сейчас доступны серии `chr` и `studchr`; JSON находятся в `public/data/<slug>/history.json`.

`vite.config.ts`, `.github/workflows/pages.yml`, JSON, схема, ID и интерфейс не требуют изменений для этой настройки. Сборка по-прежнему одна, новых зависимостей нет.
