Статус: независимый sunduev/flow-ii без прежней Git-истории; M1–M6 и расширение на N серий завершены. По поручению пользователя 6 октября настроена публикация: репозиторий публичный, Pages включён через Actions; workflow запускается при push в main либо вручную. ЧР — https://sunduev.github.io/flow-ii/chr/, СтудЧР — https://sunduev.github.io/flow-ii/studchr/. Текущая приёмка — в [отчёте](reports/2026-10-06-flow-ii-publication.md); исторические отчёты flow-chr сохранены.

Процесс работы агента описан в [AGENTS.md](../AGENTS.md): перед реализацией разбить текущий майлстоун на небольшие проверяемые задачи, применять TDD для логики и подтверждать результат проверками и ревью. Этот план и задания M1–M6 фиксируют согласованные требования; повторное согласование уже принятых решений не требуется. Планы задач сохраняются в `docs/plans/`, отчёты этапов — в `docs/reports/`.

## Цель и границы

Создать статический сайт для N независимых ежегодных турниров по решению пользователя от 5 октября 2026 года. Он показывает места команд по годам, исторические составы и полную цепочку команд каждого игрока в рамках этого турнира.

Источник — отдельная XLSX-выгрузка результатов и игроков для каждого ежегодного проведения. Образец `tournament-with-players-12826.xlsx` изучен: одна строка на игрока, 90 команд, 574 игрока, составы от 6 до 9, целые и дробные места. Город и флаг не используются; в JSON записывается только «Фамилия И.», отчество игнорируется. Точное преобразование и схема версии 1 заранее закреплены в [контракте данных](data-contract.md).

Все новые XLSX кладутся в `data/tournaments/<slug>/source/` с именами `tournament-with-players-<tournamentId>-<year>.xlsx`: например, `tournament-with-players-1710-2011.xlsx` задаёт ID источника `"1710"` и год `2011`. Отдельный скрипт извлекает ID источника и год из имени файла; пользователь задаёт название проведения. Список XLSX и параметры сохраняются в `data/tournaments/<slug>/sources.json`. Скрипт `scripts/convert-xlsx.ts` командой `npm run convert:xlsx -- <slug>` пересоздаёт только JSON выбранной серии в `public/data/<slug>/history.json`. Для ЧР ключ — `chr`; без аргументов используется серия по умолчанию из реестра. Сайт только читает готовый JSON, функции импорта на сайте нет. Демонстрационные данные M1–M3 сохранены отдельно в `data/fixtures/demo-history.json` для тестов.

Рабочий набор: 21 реальное проведение за 2001–2019, 2025–2026 годы, 420 команд, 2679 игроков и 1324 участия. Образец переименован в `tournament-with-players-12826-2026.xlsx`; названия всех проведений заданы в `data/tournaments/chr/sources.json` по согласованному шаблону «ЧР — <год>». Приёмка M5 и последующие проверки UI описаны в отчётах; параметры GitHub Pages и публичная приёмка закреплены в [отчёте M6](reports/M6.md).

По решению пользователя от 4 октября 2026 года исходные XLSX исключены из Git и его истории, но сохраняются локально в `data/tournaments/chr/source/`. Для пересоздания JSON в новом клоне нужны отдельно полученные выгрузки. Сборка и публикация используют готовый JSON из репозитория; список источников и скрипт остаются в Git.

Данные считаются корректными и полными по умолчанию. Валидация исходников и JSON, отчёты об ошибках данных, подтверждение полноты составов и разрешение конфликтов не входят в первую версию. Проверки кода, сборки и интерфейса сохраняются.

Расширение от 5 октября поддерживает N турниров: один исходный `index.html` и общие JS/CSS, отдельные XLSX, метаданные и JSON. После единственной сборки Vite готовый HTML копируется в каталог каждой серии; заголовки и пути ресурсов подставляются автоматически. ЧР — `/flow-ii/chr/`, СтудЧР — `/flow-ii/studchr/`; корень перенаправляет на ЧР. Реестр `data/tournaments.json` используется сборкой и CLI; общий JS получает только публичные настройки маршрутов (slug, name, history), выбирает серию по пути и запрашивает только её историю. Списки XLSX и сами истории в JS не включаются. Между турнирами нет навигации или связей, ID разных наборов независимы. СтудЧР содержит 26 реальных проведений за 2001–2026 годы, 671 команду, 3813 игроков и 1194 участия. Историческая публикация обеих серий и исправления склонения счётчиков подтверждена для коммита `b96bfda094e99f7612875867e712058cbed1c3cc`: 5 октября workflow завершился успешно, страницы и JSON были доступны, публичные данные побайтно совпали с локальными. 6 октября опубликован независимый flow-ii; текущая проверка — в [отчёте](reports/2026-10-06-flow-ii-publication.md). Результат — в [проверке публикации 5 октября](reports/2026-10-05-publication.md). Планы реализации: [N турниров](plans/2026-10-05-multiple-tournaments.md), [одна точка сборки](plans/2026-10-05-single-entry-build.md), [возврат редиректа](plans/2026-10-05-restore-root-redirect.md). Личные кабинеты, редактирование данных через сайт и отдельные страницы игроков не входят в требования.

## Требования к интерфейсу

Существующий [макет](references/tournament-history.html) — необязательный ориентир, а не утверждённый дизайн или цель точного воспроизведения. Можно менять композицию, оформление и детали взаимодействия для улучшения читаемости и удобства, сохраняя перечисленные сценарии продукта.

- Годы расположены колонками слева направо, от новых к старым; самый новый год слева. Год с известным `tournamentId` — ссылка на проведение на rating.chgk.info, открывающаяся в новой вкладке.
- В каждой колонке команды упорядочены по занятому месту. В узлах подписано название; место показано в карточке состава и полной доступной подписи узла.
- Фоновые связи не отображаются (доработки UI от 2 октября 2026 года). Нажатие на команду выделяет полные цепочки всех игроков её состава, включая годы до и после выбранного участия.
- Кнопка людей у активного участия открывает карточку с названием команды, годом и всем историческим составом. Место показано отдельной строкой карточки по комментарию от 3 октября 2026 года. Имена переключают фильтр игрока: повторное нажатие возвращает весь состав. Активное имя отмечено крестиком и aria-pressed. Карточка сохраняет весь список и фокус на имени.
- Фильтр игрока с крестиком расположен рядом с периодом и «Компактно». Удаление возвращает все цепочки и фокус на «Компактно». Верхней подписи команды, отдельной строки и дополнительной кнопки состава нет; кнопок «Весь состав», нижней панели и текстовых списков истории нет.
- Связанные участия с тем же `teamId`, что у активного, выделены зелёным фоном; остальные связанные — мягким светло-золотистым фоном с рамкой в золотистом оттенке. Активное участие сохраняет основное тёмно-зелёное выделение. Совпадение названий без совпадения ID не учитывается; участия вне выбранных цепочек не получают дополнительного выделения.
- Кнопка цепочки у связанного участия открывает информационный список участников выбранных цепочек и подпись источника состава, не меняя выбор.
- Карточка открывается только нажатием: на десктопе рядом с кнопкой команды, на телефоне — снизу видимой области экрана. На телефоне ширина занимает экран с полями по 12 px, высота ограничена 65% видимой области, нижний отступ учитывает безопасную область устройства. Карточка учитывает нативный зум и остаётся обычного экранного размера. Прокрутка диаграммы/страницы и перемещение увеличенного экрана на телефоне сохраняют панель у нижнего края. Крестик, Escape, повторное нажатие, отдельное нажатие вне карточки и смена диапазона/режима закрывают её; начало перетаскивания или pinch не закрывает. Изменение только высоты мобильного окна сохраняет карточку; смена ширины закрывает. На десктопе прокрутка диаграммы/страницы и изменение размера закрывают карточку. Наведение и фокус не открывают её. После выбора игрока карточка связана с новой кнопкой того же участия в SVG; Escape возвращает фокус на кнопку людей. Решение пользователя от 5 октября 2026 года с последующим возвратом нижней панели: [план карточки и выделения ID](plans/2026-10-05-mobile-roster-and-team-id.md).
- Диаграмма занимает оставшуюся высоту окна после статистики, управления и футера, прокручивается по обеим осям. «Компактно» оставляет участия выбранных цепочек; возврат восстанавливает прокрутку общей таблицы.
- Масштаб диаграммы меняется кнопками «− / текущий процент / +» в диапазоне 10–200%; нажатие процента возвращает 100%. Начальное значение — 100%. Центр видимой области сохраняется в пределах прокрутки, масштаб сохраняется при выборе команды/игрока, смене периода и «Компактно». Смена масштаба закрывает карточку состава. При масштабе меньше 100% двойной клик по диаграмме приближает область до 100%. По команде первый клик выбирает её, второй приближает; точка клика оказывается в центре, насколько позволяют края. Колесо только прокручивает диаграмму. Отдельного зума с Shift нет. SVG при зуме не пересоздаётся. По поручению от 6 октября два пальца внутри диаграммы плавно меняют её масштаб вокруг середины жеста и перемещают её по обеим осям. Процент округляется для отображения, сам масштаб остаётся плавным; кнопки выбирают ближайший меньший/больший прежний уровень. Начало жеста закрывает карточку, сохраняет выбор/фильтр; клик после жеста подавляется. Пределы — те же 10–200%. [План мобильного зума](plans/2026-10-06-touch-zoom.md).
- Диаграмму можно перетаскивать левой кнопкой мыши по обеим осям через прокрутку контейнера. Движение от 5 px подавляет клик после жеста; короткое нажатие сохраняет выбор команды, открытие состава и ссылки года. Один палец на телефоне и тачпад сохраняют нативную прокрутку. Вне диаграммы браузерный зум страницы сохраняется.
- Диапазон сохраняет выбор и фильтр даже при скрытом годе, не создаёт новых связей. Чтобы открыть состав скрытого участия, верните год в период и найдите выбранную команду на диаграмме.

### Все составы команды — уточнение 6 октября 2026 года

«Все составы» — отдельный выключенный по умолчанию переключатель рядом с «Компактно». Он объединяет уникальных игроков всех участий выбранной команды по `teamId` и показывает их полные истории, включая другие команды. Переименования сохраняют общий набор; одинаковые названия разных ID его не расширяют. Выбор другого года той же команды сохраняет набор, выбор другой команды перестраивает его; режим сохраняется, фильтр игрока сбрасывается при выборе участия, как прежде. Период ограничивает только диаграмму, компактность независима. При выключении режима фильтр сохраняется, если игрок есть в активном составе, иначе снимается.

В общем режиме у всех показанных участий выбранной команды кнопка людей открывает полный состав конкретного года с выбором игрока. Внешняя карточка связи содержит только игроков данного участия из исторического набора, с учётом фильтра, и подпись «Из составов „Выбранная команда“:». Открытие карточки другого года не меняет активное участие. Цвета линий и маркеров стабильны внутри общего набора одной команды, независимо от активного года и фильтра.

Пунктирная рамка отмечает дополнительные участия, появившиеся только благодаря игрокам других составов: в них нет ни одного игрока состава активного года. Участия обеих групп имеют сплошную рамку. Это правило сохраняется при фильтре игрока. Зелёный/золотистый цвет продолжает обозначать принадлежность команды; активное участие тёмно-зелёное со сплошной рамкой. Пунктир линий по-прежнему означает пропуск проведения игроком.

Режим опубликован 6 октября до отключения Pages; в локальной версии текстовой легенды нет. [План](plans/2026-10-06-all-rosters.md), [локальные проверки](reports/2026-10-06-all-rosters.md).

Начальное состояние: все годы, выбран победитель последнего доступного турнира, выделены линии всего его состава. При нескольких командах на первом месте используем стабильный порядок по ID. Если первого места в данных нет, выбираем команду с наименьшим указанным местом; пустой набор не должен вызывать ошибку.

## Техническое решение

Стек первой версии: **Vite + TypeScript + SVG + `d3-scale` и `d3-shape`**, обычный CSS. React для согласованного объёма не требуется.

- Vite отвечает за локальную разработку и сборку статического сайта.
- TypeScript описывает данные и состояние выбора.
- Собственная небольшая функция размещает команды: колонка определяется годом, строка — порядком в результатах.
- D3 рассчитывает шкалы и плавные SVG-линии между известными точками. Автоматическую раскладку Sankey не используем: положение команд должно соответствовать местам.
- Сайт загружает подготовленный JSON из собственных статических файлов. Постоянный сервер и база данных не нужны.
- В репозитории сохранена конфигурация GitHub Pages: workflow `.github/workflows/pages.yml` предусматривает публикацию `dist/` при push в `main` либо ручном запуске из Actions. 6 октября подтверждена публикация flow-ii; для каждого обновления проверяется workflow отправленного SHA. Сборка использует готовые JSON всех серий, преобразование XLSX в CI не запускается.
- Готовый JSON записывается компактно, без форматирующих отступов. В M6 подтверждены gzip для JSON, JS и CSS, HTTP-кеширование и ответы 304 без повторной передачи тела. Pages задаёт `Cache-Control: max-age=600`: после успешной публикации свежий кеш может сохранять прежнюю историю около 10 минут; уже открытая страница автоматически данные не перечитывает. Фактический эксперимент и ограничения CDN описаны в [отчёте M6](reports/M6.md); 5 октября `max-age=600` повторно подтверждён для страниц и JSON обеих серий.

## Индексация (6 октября 2026)

HTML всех серий и отдельно генерируемый корневой редирект содержат в исходном `<head>` ровно один `<meta name="robots" content="noindex, nofollow">`. Правило доступно до выполнения JavaScript. На текущем GitHub Pages нельзя задать собственный HTTP-заголовок `X-Robots-Tag`; JSON не имеет собственного noindex, и метатег HTML на него не распространяется. `robots.txt` в подпапке `/flow-ii/` не применяется: поисковики читают его из корня хоста. Такой файл в проект не добавляется. Правило исключения HTML действует для соблюдающих его поисковиков после обработки страницы и не закрывает прямой доступ. Метатег проверен в локальной сборке и публичных HTML корня и обеих серий flow-ii. [План и границы настройки](plans/2026-10-06-search-indexing.md).

## Модель данных и обязательные правила

Храним исходные факты, а связи и цепочки вычисляем из них. Имена не используем в качестве идентификаторов.

| Сущность | Основные поля |
| --- | --- |
| Проведение турнира | `id`, `year`, `name` |
| Команда | `id`, `name` для справочника |
| Игрок | `id`, `name` («Фамилия И.», без отчества и полного имени) |
| Участие команды | `id`, `editionId`, `teamId`, `displayName`, `place`, `playerIds` |

Название и состав в записи участия относятся к конкретному году. Переименование команды с сохранением ID не разрывает её историю. Возвращение игрока в прежнюю команду сохраняется отдельным участием в цепочке.

ID нормализуем в строки по [контракту](data-contract.md); `schemaVersion: 1`, четыре массива `editions`, `teams`, `players`, `participations`. В каждой серии одно проведение на год: его ID — строка года, ID участия — `<year>:<teamId>`. Схема и типы реализованы в M1, отдельный преобразователь XLSX — в M4. Год и внешний ID турнира извлекаются из имени XLSX, название передаётся со списком файлов; внутренние ID JSON остаются на основе года, хронология определяется годом. Необязательное поле `editions[].tournamentId` сохраняет строковый ID источника для ссылки года. Проведения, участия и вычисленные цепочки идут от старых лет к новым; справочники сортируются по строковым ID. Диаграмма разворачивает только порядок колонок. Версия схемы описывает формат, отдельный валидатор не нужен.

- Один игрок входит в состав одной команды в рамках проведения; считаем, что источник уже соблюдает это правило. Проверки повторов не реализуем.
- Цепочка показывает участия в нашем турнире, а не доказанные даты трансферов или историю участия в других соревнованиях.
- Если между известными участиями игрок пропустил проведение, которое есть в полном наборе, связь обозначается пунктиром (уточнение пользователя от 2 октября 2026 года). Соседние доступные турниры соединяются сплошной линией независимо от разницы календарных лет. Не назначаем игроку команду на годы без данных.
- Скрытие годов фильтром не считается пропуском данных и не создаёт новых связей: отображаем соответствующую часть исходной цепочки.
- Место — конечное число не меньше 1, включая дробное `6.5`; не округляем и не превращаем в предположительный диапазон. Команды с одинаковым местом получают отдельные строки и одинаковую подпись; внутри равного места используем фиксированный лексикографический порядок строковых ID команд.
- Составы считаем полными; сохраняем всех перечисленных игроков. Статус полноты и его подтверждение не нужны.
- Справочники объединяются по ID; отображаемое имя игрока и справочное название команды берутся из последнего известного проведения. Исторические названия команд остаются в участиях. Словари разрешения конфликтов не нужны.
- Скрипт пересоздаёт JSON из списка всех исходников и метаданных; исправленный год заменяет свою исходную выгрузку. Дописывать записи в готовый JSON не требуется.

## Критерии готовности первой версии

Ниже сохранены критерии приёмки M1–M6. Выполненная историческая приёмка публикации не означает, что сайт доступен сейчас: текущий статус указан в начале документа.

- Все предоставленные годы и результаты отображаются без потери записей.
- Каждая выбранная команда показывает исторически верный состав и место.
- Название каждого проведения сохранено в JSON. Карточка показывает историческое название команды, год, место и игроков; отдельная строка названия проведения удалена по согласованному упрощению интерфейса. Дробные места и игроки сверх шести не потеряны.
- Для каждого игрока выбранного состава доступна вся известная цепочка команд за все годы турнира, включая годы до и после выбранного участия.
- Пропуски и переименования не создают ложных участий и не разрывают известную историю.
- Отдельный скрипт преобразует XLSX и сохраняет готовый JSON по описанной команде; сайт читает этот файл без импорта и валидации данных.
- Сайт работает на компьютере и телефоне и не требует серверного приложения. Управление, ссылки годов, кнопки состава и игроки доступны с клавиатуры; произвольные команды выбираются мышью/касанием.
- Сайт опубликован; подготовка данных и ежегодное обновление описаны и воспроизводимы.
- На публичном адресе проверены HTTP-сжатие и кеширование; повторное открытие экономит передачу данных, публикация обновлённой истории не требует ручной очистки кеша.
