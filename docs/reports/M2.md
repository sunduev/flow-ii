## Процесс и фактические проверки

Три последовательных шага TDD: индексы, цепочки/фон, диапазон. Тесты написаны и запущены до реализации каждого шага. Красные запуски завершились по ожидаемой причине отсутствующего модуля/экспорта; после реализации соответствующие проверки прошли (2, затем 10, затем 13 тестов). После зелёных тестов упрощён тип группировки фона; итоговые проверки повторены.

- `npm test` — 13 тестов, 13 пройдено, 0 ошибок. Тесты запускаются встроенным node:test после TypeScript-компиляции только модели и вычислений в .test-build; DOM отсутствует в lib этой конфигурации.
- `npm run typecheck` — успешно.
- `npm run build` — успешно, Vite 7.3.6, статический результат в dist/.
- Ревью: нет восстановления фактов из геометрии; хронология определяется year, не текстом ID; ссылки фонового графа группируются вложенными Map без составного строкового ключа; сортировка не изменяет входные массивы; диапазон только фильтрует исходные связи, не пересчитывает цепочки.

Браузер, телефон и клавиатура в M2 не проверялись: UI не изменён, модуль ещё не подключён к странице; визуальное оформление и управление выбором относятся к M3. Тест сохранения полной истории проверяет вычислительный контракт, а сохранение состояния кнопок/выбора будет проверено при реализации M3.

## Передача M3 и ограничения

M3 получает документированный API src/history/index.ts, готовый JSON и tests/history.test.mjs. Для панели использовать getRosterHistories/getPlayerHistory и метаданные индекса, для диаграммы — getDiagramData с исходным графом buildHistoryGraph. Выбор команды/игрока хранить отдельно от проекции диапазона; API ожидает известные ID. Факты в результатах переиспользуются и предназначены для чтения без мутаций.

Приёмка M2 выполнена на условном наборе и корректных небольших примерах; это не проверка реальной истории M4–M5. Git отсутствует, коммиты не создавались. Импорт XLSX и публикация не выполнялись. Все необходимые входы M3 доступны; для M4–M5 по-прежнему нужны реальные XLSX, годы и названия проведений.
