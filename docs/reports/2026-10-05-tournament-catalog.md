# Корневой каталог турниров

Исторический документ: каталог отменён последующим решением пользователя; актуальная реализация снова перенаправляет корень на ЧР. См. [план возврата редиректа](../plans/2026-10-05-restore-root-redirect.md).

5 октября 2026 года. Корневой адрес теперь показывает список турниров из реестра; автоматического перехода на ЧР нет. Каталог не запрашивает исторические JSON. Страница выбранного турнира запрашивает только свою историю. На диаграммах меню между турнирами не добавлено. Изменения локальные, публикация не поручена.

## Замечания и изменения

- `src/main.ts`: `start()` был введён для раннего `return` после перенаправления. Обёртка удалена; top-level запуск с `await` сохранён. Каталог и загрузка выбранной истории находятся в отдельных ветвях.
- `index.html`, `src/style.css`: исходный заголовок «Инфографика», простой список ссылок с доступностью для клавиатуры. Заголовки отдельных страниц сохраняют название турнира.
- `vite.config.ts`: 16 строк вместо 38. Остались base, публичные настройки маршрутов и один build-plugin. Конфигурация работает при сборке и не входит в браузерный код.
- `scripts/site-pages.ts`: plugin перенесён сюда, удалены генерация корневого редиректа и вспомогательный middleware. Корневой HTML остаётся общей точкой входа; копирование страниц для статических адресов сохраняется. Нормализацию адреса без слеша выполняют приложение и статический сервер.
- `src/model/tournament-page.ts`, тесты: корень и `/index.html` выбирают каталог; неизвестные пути не выбирают историю, страницы серий и адреса без слеша работают как прежде. `defaultTournament` остался только в реестре для CLI.
- README, основной план, контракт и AGENTS актуализированы; [план задачи](../plans/2026-10-05-tournament-catalog.md) завершён.

## Проверки

TDD: сначала упали три проверки — корень возвращал старый редирект, а готовый корневой HTML заменялся страницей перенаправления. После реализации прошли все 59 тестов. Итоговые `npm test`, `npm run typecheck`, `npm run build`, `git diff --check` успешны. Сборка без предупреждений; top-level await поддерживается действующей конфигурацией.

Временно добавлены две записи реестра без JSON и XLSX: каталог из трёх ссылок работает без историй. `npm run dev -- --port 5176` и `npm run preview -- --port 4176` проверены браузером: каталог, переход Enter в ЧР, прямой адрес без слеша с сохранением query/hash. Итоговый `/flow-chr/index.html` также показывает каталог.

`npm run build -- --base=./` и `node scripts/serve-quality.mjs 4177`: каталог под `/full/` показывает правильные ссылки и 0 fetch. После перехода в ЧР зафиксирован ровно один fetch — `/full/data/chr/history.json`; отображены 1324 участия. На `/empty/` каталог также отображается без fetch.

Телефон 390×844: список читается, ширина документа равна 390 px, ссылка ЧР открывает диаграмму. Проверены Enter для состава и игрока, Escape с возвратом фокуса, кнопки масштаба, переход Tab между ссылками годов. Viewport восстановлен. Ошибок консоли не обнаружено.

## Сохранность и ограничения

Временные записи удалены, восстановлена обычная сборка с ЧР. Исходный JSON из HEAD, `public/data/chr/history.json` и копия в dist имеют одинаковый SHA-256:

```text
9f8db60c253385b21b7ab0e1d5376f209ca81fe67a32a0fa46bdcaa755095f0c
```

Каталог использует общий JS/CSS приложения, но не создаёт индексы историй или диаграмму и не читает их JSON. Сейчас в реестре только ЧР; для других реальных турниров ещё нужны данные. Commit, push и публикация не выполнялись.
