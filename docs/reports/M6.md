Отдельная публикация /m6-cache-probe/ использует схему истории версии 1 и обычный fetch('./history.json'), не меняя реальные данные. Версия A опубликована run 37186552265; версия B — run 37186672066. После B условный запрос с ETag версии A получил 200 и 149 байт нового JSON. Обычная перезагрузка браузера до истечения 600 секунд всё ещё показала A; контрольное открытие через 640 секунд после снимка A показало B без очистки кеша, в той же вкладке и с обычной перезагрузкой. Тестовые ресурсы удалены после проверки.

## Ограничения и приёмка

На Pages Cache-Control: max-age=600 задаётся хостингом. В проверенном браузере свежий JSON оставался прежним до истечения этого срока; после истечения обычная перезагрузка получила новую историю. Для обновления нужно дождаться успешного deployment, затем открыть сайт заново; при свежем кеше возможна задержка около 10 минут. Время распространения deployment/CDN зависит от GitHub и не гарантируется этим экспериментом. Уже открытая страница автоматически не перечитывает данные. Ручная очистка кеша не нужна.

Все критерии задания подтверждены: постоянный адрес, корректный base, текущий desktop/телефонный сценарий и клавиатура, gzip трёх ресурсов, 304 при повторной проверке, отдельная публикация обновления, воспроизводимое ежегодное обновление и исправление метаданных без изменения UI, успешные проверки. Остались только эксплуатационные ограничения: физический телефон и другие браузеры не проверены, XLSX для последующих обновлений нужно получать отдельно. Дополнительный этап разработки не требуется.
