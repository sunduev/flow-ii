# Карточка при мобильном зуме и выделение ID команды

Реализовано по решению пользователя от 5 октября 2026 года. [План](../plans/2026-10-05-mobile-roster-and-team-id.md).

Состав открывается рядом с командой на обоих размерах экрана. При нехватке места сбоку карточка появляется ниже/выше, её положение и размеры ограничены видимой областью. На телефоне прокрутка диаграммы и перемещение экрана сохраняют карточку: она следует за кнопкой, а при уходе команды за экран остаётся у края. Для нативного зума используются размеры, смещение и масштаб `visualViewport`; обратный transform сохраняет обычный экранный размер карточки. Описание API проверено по [MDN VisualViewport](https://developer.mozilla.org/en-US/docs/Web/API/VisualViewport). При отсутствии API используются размеры окна.

Внешнее закрытие перенесено с начала касания (`pointerdown`) на завершённое нажатие (`click`), поэтому начало перемещения не закрывает состав. При переключении игрока `composedPath()` отличает внутреннее нажатие от внешнего даже после замены списка. Крестик, Escape, повторное нажатие кнопки, диапазон, режим и программный зум сохраняют явное закрытие; десктопная прокрутка и resize тоже закрывают.

Связанные участия с тем же строковым `teamId`, что у активного, имеют чуть более насыщенный зелёный фон и рамку, плюс доступную подпись «та же команда, что и выбранная». Активное выделение сохраняет приоритет. Совпадение имени не используется; новые цепочки, связи и участия не добавляются. JSON обеих серий не изменён.

Изменены `src/diagram/index.ts`, `team-info.ts`, `team-info-events.ts`, добавлен `team-info-position.ts`; CSS, тесты событий/геометрии и конфигурация их компиляции, README, актуальные требования и описание диаграммы.

## Возврат нижней панели и зелёного выделения ID

По следующему уточнению пользователя участия той же команды снова зелёные (#cce3d5), остальные связанные получили золотистый фон с зелёной рамкой. На телефоне карточка возвращена к нижнему краю visual viewport. Ширина — экран с полями по 12 px, высота — до 65% видимой области, нижний отступ учитывает safe area. На десктопе сохранено размещение у кнопки. Компенсация нативного масштаба и сохранение при перемещении действуют также для нижней панели.

Три новых теста геометрии сначала упали на прежней реализации: ширина 360 вместо 366, отсутствие нижней привязки и высота 65 вместо 54 на низком экране с безопасным отступом 34. После исправления `npm test`: 68/68; `npm run build`: TypeScript и сборка успешны.
